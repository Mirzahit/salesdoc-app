# v924 — закрыть Apps Script секретом

## Что случилось

Скрипт чтения таблиц развёрнут «для всех, даже анонимных», а ссылка на него лежала прямо в
`index.html`. Значит без всякого входа в программу, зная только адрес сайта, можно было скачать:

- расходы KZ и KG — включая зарплаты и бонусы поимённо;
- лист `Users` Академии — там колонка `pass_hash`, то есть хеши паролей сотрудников;
- таблицы «Доходы» KZ и KG.

Проверено вживую 08.09.2026: запрос без единого заголовка вернул строки расходов за август.

## Что уже сделано в коде (v924)

- Браузер больше НЕ ходит в Apps Script напрямую. Все обращения идут через `/api/sheets` —
  серверный прокси, который проверяет права сотрудника (расходы → «Расходы», доходы → «Оплаты»,
  планы → «Планы»).
- Ссылки на оба скрипта убраны из `index.html`.
- Чтение листа `Users` (с хешами паролей) удалено из фронта совсем, а через прокси запрещено.
- Сервер добавляет секрет `SHEETS_TOKEN` к каждому вызову скрипта — и из прокси, и из импорта
  платежей (`api/payments.js`).

Осталось закрыть сам скрипт — иначе старая ссылка продолжает работать для любого, у кого она
сохранилась.

## Порядок действий (важен именно такой)

### Шаг 1. Vercel — задать секреты

Vercel → проект `salesdoc-app` → Settings → Environment Variables. Добавить для Production:

| Имя | Значение |
|---|---|
| `SHEETS_TOKEN` | длинная случайная строка, например `sd-sheets-9f3K2p7QxR4mT8vZ` |
| `SESSION_SECRET` | другая длинная случайная строка (нужна для личных сессий сотрудников) |

После добавления — Deployments → последний деплой → Redeploy (переменные подхватываются только
новым деплоем).

На этом шаге ничего не ломается: сервер начнёт передавать токен, а скрипт его просто игнорирует.

### Шаг 2. Apps Script — начать требовать токен

1. script.google.com → проект чтения таблиц (деплой `AKfycbwwNL4...vg/exec`).
2. Настройки проекта (шестерёнка) → «Свойства скрипта» → добавить свойство
   `SHEETS_TOKEN` со **значением ровно как в Vercel**.
3. В `Код.gs` добавить в конец файла:

```javascript
// === v924 SEC: доступ к скрипту только по секрету ===========================
// Без этой проверки скрипт отдавал расходы и хеши паролей любому анониму.
// Секрет лежит в свойствах скрипта и в env Vercel (SHEETS_TOKEN) — в коде программы его нет.
function checkToken_(e) {
  var expected = PropertiesService.getScriptProperties().getProperty('SHEETS_TOKEN');
  if (!expected) return false; // свойство не задано — не пускаем никого (лучше сломать, чем открыть)
  var got = (e && e.parameter && e.parameter.token) || '';
  if (!got && e && e.postData && e.postData.contents) {
    try { got = JSON.parse(e.postData.contents).token || ''; } catch (err) { got = ''; }
  }
  return String(got) === String(expected);
}

function denied_() {
  return ContentService
    .createTextOutput(JSON.stringify({ rows: [], error: 'Forbidden' }))
    .setMimeType(ContentService.MimeType.JSON);
}
```

4. В самое начало `doGet(e)` и `doPost(e)` добавить одну строку:

```javascript
  if (!checkToken_(e)) return denied_();
```

5. Развернуть → Управлять развёртываниями → карандаш → Версия: «Новая» → Развернуть.
   **URL должен остаться прежним** — не создавать новое развёртывание.

Он тоже отвечает анонимно и тоже отдаёт «Доходы», но программой больше не используется —

## Что это НЕ закрывает

- Общий `APP_TOKEN` всё ещё лежит в коде страницы, и по нему можно дёргать `/api/*`.
  Закроется, когда фронт перейдёт на личные сессии полностью (env `SESSION_SECRET` — первый шаг)
  и константу можно будет убрать, а токен — сменить (не забыть про бота оплат на Railway).
- Хеши паролей уже утекали — их видел любой, кто знал ссылку. Пароли сотрудникам стоит сбросить.
- База знаний читается напрямую из Google по CSV-ссылке (`gviz`), то есть таблица открыта
  «по ссылке». Это отдельная задача.
